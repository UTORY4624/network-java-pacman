# 팩맨 vs 유령 — 게임 규칙 검토 초안

관련 이슈: [#5 게임 규칙·초기 설정값·판정 순서 확정](https://github.com/UTORY4624/network-java-pacman/issues/5)

제안서에 기재된 규칙을 구현 기준으로 정리한 초안입니다. 아래의 ‘추가로 결정할 항목’은 아직 합의되지 않았으며, PR에서 검토한 뒤 선택한 값과 이유를 반영합니다. 이 문서의 작성만으로 기능 구현이나 동작 검증이 완료된 것은 아닙니다.

## 1. 실행 구성과 역할

- Java·Swing과 TCP Socket / ServerSocket을 사용합니다.
- 서버 1개와 클라이언트 2개를 실행하며 같은 네트워크의 PC 2대에서 플레이합니다.
- 한 명은 팩맨, 다른 한 명은 유령을 조작합니다.
- 같은 역할의 중복 선택과 세 번째 사용자 접속을 처리합니다.
- 서로 다른 역할의 두 사용자가 모두 준비하면 게임을 시작합니다.

## 2. 서버와 클라이언트의 책임

| 서버 | 클라이언트 |
| --- | --- |
| 접속·역할·준비 상태 관리 | 접속·역할 선택·준비 요청 전송 |
| 방향 입력에 따른 이동과 벽 충돌 계산 | 방향키 입력 전송 |
| 먹이·아이템·접촉·목숨·시간·승패 판정 | 서버가 전달한 캐릭터·먹이·게임 정보 표시 |
| 사용자별 탐지 여부 계산과 상대 좌표 전송 제한 | 탐지 범위 밖 상대의 이전 표시 제거 |
| 역할 교대·상태 초기화·라운드 중단 처리 | 결과·재대결·오류 안내와 화면 전환 |

클라이언트는 방향을 보내고 서버는 계산한 게임 상태를 주기적으로 전송합니다. 메시지 필드·메시지 경계·전송 주기는 통신 규약 이슈에서 정합니다.

## 3. 제안서의 초기 규칙

| 항목 | 기준 |
| --- | --- |
| 팩맨 승리 | 일반 먹이를 모두 수집 |
| 유령 승리 | 팩맨의 목숨을 모두 소진시키거나 제한 시간까지 먹이 수집을 저지 |
| 초기 목숨 | 팩맨 2개 |
| 제한 시간 | 180초 |
| 이동 속도 | 유령이 팩맨보다 15~20% 빠르게 시작. 구체적인 값과 단위는 추가 합의 |
| 탐지 거리 | 직선거리 5칸 이하 |
| 벽과 탐지 | 벽 유무는 탐지에 영향을 주지 않음 |
| 파워 효과 | 획득 시 5초 동안 유령 포획 가능 |
| 파워 재획득 | 남은 효과 시간을 5초로 갱신 |
| 유령 포획 후 | 시작 위치로 복귀하고 3초 후 이동 재개 |

탐지 반경·속도·효과 시간·제한 시간은 실제 테스트 후 조정할 수 있습니다. 변경 시 값과 이유를 기록합니다.

### 일반 접촉과 재개

일반 상태에서 팩맨과 유령이 접촉하면 팩맨의 목숨이 1개 감소합니다. 목숨이 남으면 두 캐릭터를 시작 위치로 재배치하고 3초 후 재개합니다. 이미 수집한 먹이는 복원하지 않습니다. 목숨이 모두 소진되면 승패를 판정합니다.

### 탐지와 정보 공유

- 거리가 5칸 이하이면 서로 표시합니다. 5칸을 넘으면 상대 표시를 제거합니다.
- 서버는 본인 위치와 공통 상태를 보내되, 범위 밖 상대 좌표는 보내지 않습니다.
- 클라이언트는 상대가 범위 밖으로 나가면 이전 좌표로 계속 그리지 않습니다.
- 먹이 변화는 탐지 범위와 관계없이 두 사람에게 공유합니다.
- 파워 효과 중에도 탐지 규칙은 유지합니다.

### 판정 순서와 우선순위

한 번의 게임 갱신에서 다음 순서로 처리합니다.

1. 이동
2. 먹이·아이템
3. 접촉
4. 승패

마지막 먹이 수집과 치명적 접촉이 같은 갱신에서 발생하면 유령이 승리합니다. 마지막 먹이를 처리한 순간 바로 팩맨 승리를 확정하지 않고 접촉까지 처리한 뒤 승패를 확정해야 합니다.

## 4. 라운드 흐름

```text
접속 → 역할 선택 → 양측 준비 → 게임 진행 → 결과
                                  ↓
                      역할 교대 → 양측 준비 → 새 라운드
```

- 종료 후 역할을 바꾸고 두 사용자가 준비하면 상태를 초기화해 재대결합니다.
- 상대가 종료하면 진행 중인 라운드를 중단하고 남은 사용자는 대기 화면으로 돌아갑니다.
- 접속 실패와 상대 종료는 사용자에게 안내합니다.

## 5. 추가로 결정할 항목

다음 항목은 제안서에 구체적인 값이나 처리 방식이 없어 검토가 필요합니다. 임의로 확정하지 않고 PR에서 합의합니다.

| 항목 | 검토할 내용 |
| --- | --- |
| 속도 | 팩맨 기본 속도와 단위, 유령의 구체적인 초기 배율 |
| 팩맨 재배치 대기 | 3초 동안 제한 시간과 파워 효과 시간이 흐르는지 |
| 유령 복귀 대기 | 유령의 3초 대기 중 팩맨 이동·제한 시간·파워 효과의 진행 방식 |
| 추가 동시 발생 | 마지막 먹이와 시간 초과가 겹치는 경우 등 판정 우선순위 |
| 재대결 초기화 | 위치·먹이·목숨·효과·시간·탐지·준비·이전 입력 중 초기화·유지할 항목 |

## 6. 규칙 검토 사례

아래는 문서 검토용 기대 결과입니다. 실제 코드에서의 확인은 각 기능 이슈에서 수행합니다.

| 조건 | 제안서 기준 기대 결과 |

| 제한 시간까지 일반 먹이 수집 미완료 | 유령 승리 |
| 게임 중 상대 종료 | 라운드 중단, 남은 사용자 대기 화면 복귀 |
