# 팩맨 vs 유령 — 게임 규칙 검토 초안

관련 이슈: [#5 게임 규칙·초기 설정값·판정 순서 확정](https://github.com/UTORY4624/network-java-pacman/issues/5)

제안서에 기재된 규칙을 구현 기준으로 정리하고, 제안서에 없는 세부 조건에는 신유석의 검토용 제안을 추가한 문서입니다. 3절은 제안서 기준, 5절은 이번 PR에서 검토할 추가 제안입니다. 추가 제안은 팀원 합의 전이며, 문서 작성만으로 기능 구현이나 동작 검증이 완료된 것은 아닙니다.

## 1. 실행 구성과 역할

- Java·Swing과 TCP Socket / ServerSocket을 사용합니다.
- 서버 1개와 클라이언트 2개를 실행하며 같은 네트워크의 PC 2대에서 플레이합니다.
- 한 명은 팩맨, 다른 한 명은 유령을 조작합니다.
- 같은 역할의 중복 선택과 세 번째 사용자 접속을 처리합니다.
- 서로 다른 역할의 두 사용자가 모두 준비하면 게임을 시작합니다.

## 2. 서버와 클라이언트의 책임

| 서버 | 클라이언트 |
| --- | --- |
| 접속·역할·준비 상태 관리 | 접속·역할 선택·준비 요청 전송 |
| 방향 입력에 따른 이동과 벽 충돌 계산 | 방향키 입력 전송 |
| 먹이·아이템·접촉·목숨·시간·승패 판정 | 서버가 전달한 캐릭터·먹이·게임 정보 표시 |
| 사용자별 탐지 여부 계산과 상대 좌표 전송 제한 | 탐지 범위 밖 상대의 이전 표시 제거 |
| 역할 교대·상태 초기화·라운드 중단 처리 | 결과·재대결·오류 안내와 화면 전환 |

클라이언트는 방향을 보내고 서버는 계산한 게임 상태를 주기적으로 전송합니다. 메시지 필드·메시지 경계·전송 주기는 통신 규약 이슈에서 정합니다.

## 3. 제안서의 초기 규칙

| 항목 | 기준 |
| --- | --- |
| 팩맨 승리 | 일반 먹이를 모두 수집 |
| 유령 승리 | 팩맨의 목숨을 모두 소진시키거나 제한 시간까지 먹이 수집을 저지 |
| 초기 목숨 | 팩맨 2개 |
| 제한 시간 | 180초 |
| 이동 속도 | 유령이 팩맨보다 15~20% 빠르게 시작. 구체적인 값과 단위는 추가 합의 |
| 탐지 거리 | 직선거리 5칸 이하 |
| 벽과 탐지 | 벽 유무는 탐지에 영향을 주지 않음 |
| 파워 효과 | 획득 시 5초 동안 유령 포획 가능 |
| 파워 재획득 | 남은 효과 시간을 5초로 갱신 |
| 유령 포획 후 | 시작 위치로 복귀하고 3초 후 이동 재개 |

탐지 반경·속도·효과 시간·제한 시간은 실제 테스트 후 조정할 수 있습니다. 변경 시 값과 이유를 기록합니다.

### 일반 접촉과 재개

일반 상태에서 팩맨과 유령이 접촉하면 팩맨의 목숨이 1개 감소합니다. 목숨이 남으면 두 캐릭터를 시작 위치로 재배치하고 3초 후 재개합니다. 이미 수집한 먹이는 복원하지 않습니다. 목숨이 모두 소진되면 승패를 판정합니다.

### 탐지와 정보 공유

- 거리가 5칸 이하이면 서로 표시합니다. 5칸을 넘으면 상대 표시를 제거합니다.
- 서버는 본인 위치와 공통 상태를 보내되, 범위 밖 상대 좌표는 보내지 않습니다.
- 클라이언트는 상대가 범위 밖으로 나가면 이전 좌표로 계속 그리지 않습니다.
- 먹이 변화는 탐지 범위와 관계없이 두 사람에게 공유합니다.
- 파워 효과 중에도 탐지 규칙은 유지합니다.

### 판정 순서와 우선순위

한 번의 게임 갱신에서 다음 순서로 처리합니다.

1. 이동
2. 먹이·아이템
3. 접촉
4. 승패

마지막 먹이 수집과 치명적 접촉이 같은 갱신에서 발생하면 유령이 승리합니다. 마지막 먹이를 처리한 순간 바로 팩맨 승리를 확정하지 않고 접촉까지 처리한 뒤 승패를 확정해야 합니다. 시간 초과까지 겹치는 경우의 구체적인 우선순위는 5절의 추가 제안으로 검토합니다.

## 4. 라운드 흐름

```text
접속 → 역할 선택 → 양측 준비 → 게임 진행 → 결과
결과 → 역할 교대 → 양측 준비 → 새 라운드
```

- 종료 후 역할을 바꾸고 두 사용자가 준비하면 상태를 초기화해 재대결합니다.
- 상대가 종료하면 진행 중인 라운드를 중단하고 남은 사용자는 대기 화면으로 돌아갑니다.
- 접속 실패와 상대 종료는 사용자에게 안내합니다.

## 5. 세부 규칙 제안 — 팀원 검토 전

다음은 제안서에서 구체적으로 정하지 않은 조건에 대한 제안입니다. 팀원 검토 후 합의한 내용을 구현 기준으로 채택합니다.

### 이동 속도

- 팩맨: 초당 5칸
- 유령: 초당 5.75칸, 팩맨의 1.15배
- 이유: 제안서의 15~20% 범위에서 15% 차이로 먼저 테스트합니다.
- 두 값은 첫 플레이 테스트용 초기값입니다. 실제 플레이 후 속도를 변경하면 값과 이유를 기록합니다.

### 팩맨 재배치 대기

- 목숨이 남아 재배치하는 3초 동안 두 캐릭터의 이동을 중지합니다.
- 제한 시간과 파워 효과 시간도 정지합니다.
- 이유: 재개 준비 시간 때문에 실제 플레이 시간이 줄어들지 않도록 합니다.

### 유령 복귀 대기

- 파워 상태에서 잡힌 유령만 시작 위치에서 3초 동안 대기합니다.
- 이때 팩맨의 이동, 제한 시간, 파워 효과 시간은 계속 진행합니다.
- 복귀 대기 중 유령은 이동과 접촉 판정에서 제외합니다.
- 이유: 유령을 잡은 보상을 먹이 수집 기회로 주고, 대기 중인 유령을 연속 포획하거나 접촉하는 상황을 방지합니다.

### 승패 판정 우선순위

이동 → 먹이·아이템 → 접촉을 처리한 뒤, 아래 순서대로 검사해 처음 해당하는 결과로 종료합니다.

1. 팩맨 목숨이 0이면 유령 승리
2. 일반 먹이가 모두 없어졌으면 팩맨 승리
3. 제한 시간이 끝났으면 유령 승리

마지막 먹이와 시간 초과만 겹치면 해당 갱신에서 수집을 완료한 것으로 인정해 팩맨이 승리합니다. 치명적 접촉까지 겹쳐 목숨이 0이 되면 제안서대로 유령이 승리합니다.

### 재대결 초기화와 입력

| 처리 | 항목 |
| --- | --- |
| 유지 | 두 사용자의 서버 연결 |
| 교대 | 팩맨·유령 역할 |
| 초기화 | 위치, 먹이·아이템, 목숨 2개, 제한 시간 180초, 파워 효과, 복귀·재배치 대기, 탐지 표시, 이전 방향 입력, 결과, 준비 상태 |
| 시작 조건 | 교대된 역할을 확인하고 양쪽 모두 다시 준비 |

대기·결과 화면에서는 방향 입력을 적용하지 않습니다. 팩맨 재배치 대기 중에는 두 캐릭터의 방향 입력을 적용하지 않고, 유령 복귀 대기 중에는 해당 유령의 방향 입력을 적용하지 않습니다. 대기 중 입력을 쌓아두지 않으며 재개 후 새로 누른 방향부터 처리합니다. 이전 입력으로 재개 직후 캐릭터가 갑자기 움직이는 상황을 방지하기 위한 제안입니다.

## 6. 규칙 검토 사례

아래는 제안서 기준과 5절의 추가 제안을 적용했을 때의 문서 검토용 기대 결과입니다. 실제 코드에서의 확인은 각 기능 이슈에서 수행합니다.

| 조건 | 기대 결과 |
| --- | --- |
| 두 사용자 중 한 명만 준비 | 게임 시작 전 대기 |
| 일반 상태에서 접촉하고 목숨이 남음 | 목숨 1개 감소, 두 캐릭터 재배치, 먹이 유지, 3초 후 재개 |
| 팩맨 재배치 대기 중 | 두 캐릭터 이동·제한 시간·파워 효과 시간 정지. 대기 중 방향 입력은 저장하지 않음 (추가 제안) |
| 거리 정확히 5칸 | 상대 좌표 전송·표시 |
| 거리 5칸 초과 | 상대 좌표 제외, 이전 표시 제거, 먹이 변화는 계속 공유 |
| 파워 효과가 남은 상태에서 파워 아이템 재획득 | 효과 시간을 5초로 갱신 |
| 파워 상태에서 유령 포획 | 유령 시작 위치 복귀, 3초 후 이동 재개 |
| 유령 복귀 대기 중 | 팩맨·제한 시간·파워 시간은 계속 진행. 대기 유령 이동·접촉 제외 (추가 제안) |
| 마지막 먹이와 치명적 접촉 동시 발생 | 유령 승리 |
| 마지막 먹이와 시간 초과 동시 발생, 목숨이 남음 | 팩맨 승리 (추가 제안) |
| 마지막 먹이·치명적 접촉·시간 초과 모두 동시 발생 | 유령 승리 (추가 제안의 우선순위 적용) |
| 제한 시간까지 일반 먹이 수집 미완료 | 유령 승리 |
| 재대결 시작 | 연결 유지·역할 교대, 위치·먹이·목숨·시간·효과·입력 등 초기화 (추가 제안) |
| 게임 중 상대 종료 | 라운드 중단, 남은 사용자 대기 화면 복귀 |
