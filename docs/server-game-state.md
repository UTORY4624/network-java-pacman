# 서버 게임 상태 관리 (#11)

## 이번에 만든 부분

- 원본 level/level.csv를 읽어 벽, 빈 칸, 먹이, 파워 아이템, 시작 위치를 구분한다.
- 두 명이 서로 다른 역할로 준비하면 새 GameState를 만든 뒤 GAME_START를 보낸다.
- 라운드마다 위치, 방향 입력, 목숨 2개, 제한 시간 180초, 파워 시간 0, 먹이 배열을 새로 만든다.
- 상대가 나가거나 서버가 종료되면 진행 중인 GameState를 비운다.
- 원본 게임의 이미지나 Swing 창을 생성하지 않는다.

## 원본에서 재사용한 내용

Game은 CSV를 읽으면서 Pacman과 Ghost를 만들고 GameLauncher의 UI도 연결한다.
MovingEntity는 생성할 때 이미지를 읽으며, 이동 범위도 GameplayPanel에 의존한다.
CollisionDetector는 원본 Game의 엔티티 목록을, WallCollisionDetector는 Game의 정적 벽 목록을 사용한다.
따라서 서버에서 원본 Game을 그대로 생성하지 않고 CSV 파일과 기호의 의미만 재사용했다.
이동 계산과 먹이 획득 판정은 각각 후속 이슈에서 서버 상태를 기준으로 연결한다.

## 데이터 기준

맵은 가로 56칸, 세로 62칸이다. 일반 먹이 240개와 파워 아이템 4개가 있다.
좌표는 왼쪽 위를 (0, 0)으로 하는 CSV 칸 번호이고, 배열은 [y][x] 순서다.
팩맨은 P 위치인 (26, 45), 조작할 유령은 b 위치인 (26, 21)에서 시작한다.
원본의 나머지 유령 위치 p, i, c는 추가 플레이어로 만들지 않는다.
x는 벽, -는 유령 출입문이다. 문은 일반 벽과 별도로 조회하도록 남겨뒀다.

원본은 CSV 한 칸을 8픽셀로 표시하고 캐릭터 크기는 32픽셀이다.
새 상태의 x, y는 원본 위치를 8로 나눈 칸 좌표다.
#12에서 이동과 충돌을 연결할 때는 캐릭터의 충돌 영역과 출입문 규칙을 함께 정해야 한다.
이번 작업의 isWall은 맵의 벽 여부 조회이며 캐릭터 전체 충돌 판정은 아니다.

## 후속 작업 연결

- GameMap: 변경하지 않는 원본 맵과 역할별 시작 좌표.
- PlayerState: 연결 번호, 역할, 시작/현재 위치, 방향, 대기 상태.
- GameState: 두 플레이어, 라운드 번호, 목숨, 시간, 라운드별 먹이 배열.
- PacmanServer: 생성과 종료 담당. 상태 접근은 서버의 synchronized 블록 안에서 처리한다.

direction의 초기 LEFT는 표시용 방향이다. requestedDirection은 null로 시작하므로 자동 이동을 뜻하지 않는다.
시간은 초기값만 저장하며 아직 감소하지 않는다.
#12에서 MOVE 처리, 이동 속도, 벽 충돌, 주기적인 GAME_STATE 전송을 연결한다.
먹이 수집, 접촉 판정, 승패, 자동 역할 교대와 결과 화면도 이번 범위에 포함하지 않았다.
클라이언트 화면은 기존과 동일하게 라운드 시작 안내까지만 표시한다.

## 실행과 확인

저장소에서 .\server.ps1 -Task test를 실행하면 화면 없는 초기화 테스트와 TCP 테스트를 실행한다.
GameStateTests는 원본 맵, 초기 상태, 잘못된 맵, 라운드 사이 데이터 분리를 확인한다.
ServerTests는 준비 전 상태가 없는지, 두 명 준비 후 생성되는지, 퇴장 후 비워지는지와 재접속 후 새 판 생성을 확인한다.
Eclipse에서는 프로젝트 Refresh 후 GameStateTests를 Java Application으로 실행해도 된다.
src/resources가 소스 폴더여야 한다. server.ps1은 실행 클래스와 서버 JAR에 같은 맵 파일을 포함한다.
