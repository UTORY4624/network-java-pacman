# 서버 게임 진행·승패·재대결 (#12, #14, #16, #18, #20)

## 구현 범위

기존 접속·역할·준비·초기 상태 생성에 다음 처리를 연결했다.

- `MOVE UP|DOWN|LEFT|RIGHT`: 연결 번호로 본인 캐릭터에만 입력 적용.
- 10ms 서버 갱신을 내부 1ms 단계로 처리. 팩맨 5칸/초, 유령 5.75칸/초.
- 마지막 요청 방향으로 이동하며 벽이면 정지한다. 다른 방향을 요청하면 다음 이동 시도부터 반영한다.
- 원본 CSV 1칸은 8px, 캐릭터는 32px(4×4칸)이다. 좌표는 왼쪽 위 칸이며 몸체 전체로 벽·맵 경계를 검사한다. 맵 밖으로 순간이동하지 않는다. 팩맨은 유령 문을 통과하지 못하고 유령은 통과한다.
- 원본의 일반 먹이 위치(CSV 좌표 + 8px, 크기 4px), 파워 아이템 크기(16px), 팩맨 중심점 접촉 방식을 서버 좌표로 옮겼다. 원본 Swing 객체는 생성하지 않는다.
- 이동 → 먹이·파워 획득 → 접촉 → 승패 순서. 일반 접촉은 목숨 1개 감소, 생존 시 두 캐릭터 재배치 및 3초 대기. 먹이는 복원하지 않는다.
- 파워 획득·재획득은 5초로 설정. 파워 접촉 시 유령만 시작점으로 복귀해 3초 대기한다.
- 팩맨 재배치 중 두 캐릭터·제한 시간·효과 시간이 정지한다. 유령 복귀 중에는 팩맨·제한 시간·효과 시간이 진행된다.
- 대기 중 입력은 저장하지 않는다. 재개 후 새 방향 요청이 필요하다.
- `GAME_START` 바로 다음에 첫 `GAME_STATE`를 전송한다. 이후 100ms마다, 수집·접촉·효과 만료·대기 종료 직후(서버 갱신 단위 최대 10ms)에 전송한다. 양쪽은 같은 sequence와 먹이를 받고 self/opponent만 서로 바뀐다.
- 상태 수정·스냅샷은 서버 잠금 안에서 처리한다. 상대 종료 시 기존 상태 전송을 중단하고 서버 종료 시 갱신 스레드도 종료한다.

속도와 대기 시간 처리는 병합된 규칙 PR #26의 값을 적용했다. `game-rules.md`의 검토 전 표기는 과거 문서 표현이며, 실제 밸런스 조정은 #24에서 한다.

#13·#15 화면 연결은 PR #35·#36으로 반영됐다. #16은 5칸 이하 상대만 공개하고, 범위 밖이면 `opponent: null`로 이전 표시를 지운다. 먹이와 본인 정보는 계속 공유한다. 유령 화면에서는 범위 밖 팩맨의 목숨·파워 정보도 숨겨진다.

## 승패와 재대결
- 내부 1ms 갱신에서 접촉까지 처리한 뒤 목숨 소진 > 일반 먹이 완료 > 시간 초과 순으로 판정한다.
- 마지막 먹이와 시간 초과만 겹치면 팩맨 승리, 치명적 접촉까지 겹치면 유령 승리다. 파워 아이템은 일반 먹이 완료 조건에서 제외한다.
- 종료 후 상태를 RESULT로 고정하고 이전 방향 입력·이동 적립·대기를 제거한다. 남은 갱신은 진행하지 않는다.
- 마지막 GAME_STATE 다음에 양측 동일 ROUND_RESULT를 한 번 보낸다. 결과 대기 중 주기 상태 전송과 MOVE/ROLE/READY를 막는다.
- 결과 전송 다음 틱부터 3초 뒤 역할을 교대하고 ready=false인 LOBBY를 보낸다. 연결은 유지한다.
- 양측이 다시 READY를 보낼 때만 새 GameState를 생성한다. 한 명만 준비하면 시작하지 않는다.
- 새 라운드는 위치·먹이·파워 아이템·목숨·시간·효과·대기·입력·탐지·sequence·결과를 초기화한다.
- 결과 대기 중 퇴장하면 해당 라운드의 교대 대기를 취소한다.

## 머지 전 확인

main에 합치지 않고 이 브랜치에서 확인한다. 기존 작업 폴더에 미완료 수정이 있으면 별도 폴더에 Clone한다.

```powershell
git fetch origin
git switch codex/server-round-result
.\server.ps1 -Task test
.\server.ps1 -Task build
```

`test`는 외부 라이브러리 없이 JDK 8 이상에서 실행한다.

- GameStateTests: 원본 맵·초기 상태·새 라운드 배열 분리.
- DetectionTests: 정확히 5칸·5칸 초과·대각선·벽 너머·파워 중 탐지, 재진입/이탈, 숨김과 먹이 공유.
- GameplayTests: 가상 경과 시간으로 속도·벽·4×4 충돌 영역·먹이·아이템·재배치·복귀·시간 경계 검사.
- ServerTests: 실제 로컬 TCP 소켓 두 개로 시작 직후/주기적 상태, 메시지 분할, 역할별 이동 입력, 양쪽 위치·먹이 수신, 퇴장 후 전송 중지 검사.
- RoundResultTests / RoundLifecycleTests: 판정 조합, 실제 마지막 1ms 경계 및 결과 이후 상태 불변.
- RematchTests: 실제 TCP 결과 1회 전송, 결과 단계 입력 거절, 3회 재대결, 초기값 복원, 결과 대기 중 퇴장.
- ConnectionTests: 기존 클라이언트 연결 회귀 검사.

Eclipse에서는 Refresh 후 위 테스트 클래스들을 Java Application으로 실행해도 된다. `src/resources`가 소스 폴더여야 한다. 전체 원본 게임은 JDK 21 환경을 사용한다.

서버를 직접 켜려면 `.\server.ps1 -Task run`, 접속 창은 다른 터미널에서 `.\server.ps1 -Task connect`를 두 번 실행한다. 서로 다른 역할을 고르고 둘 다 준비한 뒤 방향키로 이동한다. 가까워지면 상대가 나타나고 멀어지면 사라지며, 먹이 변화는 양쪽에 계속 보인다. `.\server.ps1 -Task test-ui`는 두 창을 연결해 5칸 진입·6칸 이탈과 기존 상대 표시 제거를 자동 확인한다. 실제 PC 두 대 검증은 #24에서 진행한다.
